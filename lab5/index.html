Lab 5: Interactive Network Visualization with D3

Urban Transit Network

A synthetic medium-sized city with 50 stations across five districts (Central, North, South, East, West), connected by 50 direct Metro, Express, and Shuttle routes. The same network is encoded twice: as an interactive force-directed node-link diagram and as an adjacency matrix.

Dataset Description

Stations and Routes

Each of the 50 stations carries three attributes: district (which of the five districts it sits in), daily_passengers (approximate average daily volume), and station_type (Local, Transfer, or Terminal). Each of the 50 routes is a direct, undirected connection between two stations with two attributes: travel_time_min and route_type (Metro, Express, or Shuttle). Data is loaded externally from data/lab5_assignment_stations.csv and data/lab5_assignment_routes.csv.

Design Description

How the Node-Link View Is Encoded

District → node color, because district is a geographic category and color is the strongest channel for categorical grouping; clusters of same-colored stations immediately show where each district sits in the topology. Daily passengers → node area (square-root scale), so that heavily used stations read as physically bigger stops without area exaggerating differences linearly. Station type → node shape (circle = Local, square = Transfer, triangle = Terminal), since shape separates functional roles without competing with the district colors. Travel time → link width, making slow direct connections visually heavy so they stand out as potential bottlenecks. Route type → link color, letting Metro, Express, and Shuttle services be traced across the map.

Interaction does the identification work that static encodings cannot: dragging lets the reader pull a station out of a cluster to untangle its links; hover highlighting fades everything except a station and its direct neighbors, exposing each node's degree; and tooltips identify the exact station with all three attributes, which is essential with 50 nodes where permanent labels would overlap.

Design Description

How the Matrix Is Encoded

Rows and columns both represent stations, and a filled cell marks a direct connection. Cell color → route type and cell opacity → travel time, so every populated cell carries both link attributes with the same color language as the node-link view. Label color → district, folding a node attribute into the matrix margins.

The key choice is ordering: stations are sorted by district, then by station type (Terminal → Transfer → Local) within each district. Grouping by district turns district-to-district connectivity into rectangular bands that can be counted and compared at a glance — something the hairball of a 50-node diagram hides. I deliberately did not encode daily passenger volume or station type inside the cells: with 2,500 cells, an additional size or shape channel would make the matrix unreadable, and those attributes are already carried by the node-link view and the tooltips.

Network Questions and Findings

Six Questions, Read from the Visualizations

1. Which stations appear central in the network?

Node-link view, answered well. Hovering a station fades everything except its neighbors, so degree is directly visible. The network is sparse — the highest degree is only 3 — and fourteen stations share that maximum (including the triangles Stations 4, 7, 10, 13, 16, 25, 31, and 34). No single dominant hub exists; centrality is spread across many small local hubs, and Terminal stations are the most connected on average (mean degree 2.12 vs. 1.88 for Locals).

2. Which districts are strongly connected to one another?

Adjacency matrix, answered well. Because rows and columns are ordered by district, district-to-district links form colored blocks. The East–South block is clearly the densest (11 direct links), followed by Central–North (9) and East–West (9), while the North–West block contains a single cell. This comparison is much harder in the node-link view, where cross-district links tangle.

3. Where are transfer or terminal stations located in the topology?

Node-link view, answered partially. The shape encoding shows that triangles (Terminals) and squares (Transfers) are spread through every district rather than clustered in one part of the map, and hover highlighting shows Terminals tend to be the small local hubs (average degree 2.12 vs. 1.88 for Locals). Precise "location in the topology" is only approximate, since a force layout has no stable geographic coordinates.

4. Which stations have high passenger volume?

Node-link view, answered well. Node area encodes daily passengers, so the busiest stations are literally the largest marks: Stations 46–50 stand out as the five biggest nodes, one in each district (roughly 9,200–9,850 passengers/day, confirmed via tooltip). The smallest circles are visibly an order of magnitude lighter in volume.

5. Where are the longest direct travel-time connections?

Both views, answered well. In the node-link diagram, link width makes the slowest routes the thickest strokes; in the matrix, the same links are the darkest cells. The three heaviest links are Station 7 ↔ Station 31 (16 min), Station 18 ↔ Station 34 (15 min), and Station 29 ↔ Station 50 (14 min) — all orange, i.e. Express routes, which fits their role as long cross-city connections.

6. Are particular route types concentrated in particular parts of the network?

Both views, answered well. Link and cell colors show that Metro, Express, and Shuttle links are interleaved throughout all five districts rather than segregated; the matrix's colored cells appear scattered across every district block with no monochrome band. The counts are nearly equal (17 Express, 17 Shuttle, 16 Metro), so no route type dominates any part of the city.
